## Binaries in a package

| File | What it is |
|---|---|
| `veyla.exe` | GPUI shell, the product UI |
| `veyla-engine.exe` | headless engine (streaming, decoder, AI, bridge) |
| `veyla-classic.exe` | previous C++ shell (still has the old Console page) |
| `veyla-legacy.exe` | original 0.5 reference shell |
| `update.exe` | single-file updater (`brp_update.exe` renamed at packaging) |

Package size is ~620 MB zipped because of `nvidia-vfx/runtime` (~475 MB, legacy
VFG backend) and `nr` (~194 MB, DLSS-G/SR runtimes). A "lite" build is possible
but not done.

## Build

```powershell
cmake --build build-perf --config Release --target brpnext brpnext-engine brp brp_update --parallel 8
powershell -File tools\build_ui.ps1          # Rust shell, adds fxc.exe to PATH
powershell -File tools\package_release.ps1 -Version 2.7.2
powershell -File tools\make_update.ps1 -BaselineFolder dist\_floor-2.7.0 `
    -NewFolder dist\Veyla -Version 2.7.2 -Out dist\Veyla-2.7.2-update.exe
```

`build-perf` is the working build tree; the shell in development finds the
engine in `build-perf\Release` or `build\Release`. Tests: `brp_next_tests.exe`
prints `ALL PASS`.

## Update system (2.7.x)

- **Cumulative from a fixed floor.** Every patch is a diff from
  `dist\_floor-2.7.0`, not from the previous release. Any install ≥ 2.7.0 can
  skip releases safely; files added or removed since the floor are included in
  the payload. Size stays ~6 MB.
- **Checksum manifest.** `tools\make_update.ps1` writes `_manifest.txt`
  (`sha256  path`) into the payload.
- **Staged apply.** The updater unpacks to `_update_stage`, verifies every hash,
  copies with retries, applies `_delete.txt`, writes `version.txt`, removes the
  stage, then relaunches.
- **Visible failure.** On any failure it writes `update-failed.txt` next to the
  app, relaunches the existing build, and the shell shows the reason on start.
- **Log.** Everything goes to `%TEMP%\veyla-update.log`.
- **Older installs.** Below 2.7.0 the button in the app is broken (fixed in
  2.6.2/2.7.x); release notes tell people to use the standalone zip.
- `tools\publish_release.ps1` uses `-FloorFolder` (default `dist\_floor-2.7.0`).
  `general.update_repo` defaults to `bulinatu/Veyla`.

Release history: 2.6.0, 2.6.1, 2.6.2, 2.6.5, 2.7.0, 2.7.1, 2.7.2.

## User data

- Settings: `%APPDATA%\BetterRemotePlayNext\next-settings.json` (flat JSON).
- Pairing/credentials: `%APPDATA%\BetterRemotePlayNext\session.json`; the engine
  falls back to `%APPDATA%\BetterRemotePlay\session.json`.
- Backups made during testing: `%APPDATA%\BetterRemotePlayNext\backup-2026-11-28-0007`
  (contains the original `session.json` from both folders).
- Saved profiles: `%APPDATA%\BetterRemotePlayNext\profiles\*.json`, max 12.

## UI

- **Dock** at the bottom: Home, Stream, Video, Audio, Controller, Overlay,
  Settings; icon + label, sliding pill, page fade. Logo and window buttons float
  in the top bar area (no header bar).
- **Settings** has sub-pages: Appearance, Pairing, Updates, System, Diagnostics,
  About.
- **Themes** (Settings > Appearance): Aurora, Ocean, Emerald, Ember, Rose,
  Graphite, stored as `ui.palette` (0–5). Accents, aurora blobs, wash, dock,
  buttons, slider and control center follow the palette.
- **First-run chip** "Set up your PS5", centred just above the dock, only while
  no console is paired; opens Settings > Pairing. Hidden on the Pairing page.
- **Pairing**: Discover (LAN), Use, 8-digit PIN, optional PSN login (URL +
  redirect). Engine commands: `discover`, `console_use <ip>`, `pair <pin>`,
  `psn-open`, `psn-complete <url>`.
- **Control center** (F10): GPUI window, tabs Info/SR/FG/Neural/Video/Stream/
  Audio/Pad/Profile; opens even before connecting. Slider rows stack label over
  the slider so text cannot be squeezed.
- **Window behaviour**: maximize button toggles (gpui only maximizes, so restore
  uses `SW_RESTORE`); the shell strips `WS_EX_TOPMOST` about once a second so it
  can never stay above other applications.
- **Background**: aurora approximated with 72 concentric rings per blob,
  shoulder 0.78, peak 3.2; the top wash colour comes from the palette.

## Streaming and latency decisions

- 60 fps on the wire, frame buffer 0, present-on-arrival, vsync off in the
  lowest-latency preset; 30 fps content stays 60 and frame generation covers the
  cadence.
- Decoded-frame queue capped at 2 when frame buffer is 0 (6 otherwise).
- Optimize detects the default route link type: Wi-Fi → 30 Mbps and frame
  generation off; Ethernet keeps 100 Mbps.
- Optimize retries the device list and falls back to the status snapshot; it no
  longer fails with "engine did not report hardware".

## Site

- Static, hand-written HTML/CSS/JS in `docs/` (source of truth), mirrored to
  `veyla-app/veyla-app.github.io` (GitHub Actions deploy).
- No screenshots: Home, Settings and Control center are live HTML/CSS renders;
  the hero has live counters, the pipeline has an animated dot, and the compare
  section draws animated canvas charts (delay / frame time / FPS) for "typical
  stream" vs Veyla.
- Themes on the site drive `--accent`, `--wash` and `--blob-1..5`, so the aurora
  matches the palette.
- FAQ items are always open (no accordion). Support chip in the header and a
  support block in the footer.
- **Cache busting**: the stylesheet/script links carry `?v=N`. Bump N when
  changing `site.css` or `site.js`, otherwise GitHub's CDN keeps serving the old
  file for minutes.
- Pages settings for the site repo: build type `workflow`.

## Known limitations

- **PS4**: HEVC-only video path; PS4 Remote Play is H.264. Discovery, pairing
  and input already work for PS4.
- No HDR pipeline.
- Builds are unsigned (SmartScreen warnings).
- Package is large (see above).
- True gaussian blur is not possible in GPUI; the ring approximation is what
  ships. A pre-rendered bitmap background would be the next step if wanted.
